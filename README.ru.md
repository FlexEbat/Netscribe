# Netscribe

[English](README.md) · **Русский**

Netscribe сканирует сеть и записывает, что нашёл. Он находит устройства по ARP, читает их
имена, интерфейсы и соседей по SNMP и SSH, перечисляет открытые сервисы и контейнеры Docker
и хранит историю каждого скана. Результат смотрят в веб-панели и выгружают в Markdown, HTML,
PDF или схему Draw.io.

Это один статический бинарник со встроенным веб-интерфейсом и базой SQLite. Пакеты уходят
только на цели, которые вы настроили, телеметрии нет. Только Linux (amd64, arm64).

## Что он делает

| Что вы получаете | Как |
| --- | --- |
| Инвентарь устройств, адресов, связей, сервисов и контейнеров | Пробы ARP, ICMP и TCP, SNMP v2c, LLDP, таблицы маршрутизаторов, HTTP-баннеры, mDNS, SSDP, SSH, Docker, необязательный Nmap |
| Топологию, которую можно читать и править | Слоистая карта в панели; устройства и связи, которые никто не находит, добавляются вручную |

| Панель для команды | Вход по паролю, три роли (`viewer`, `operator`, `admin`), токены доступа, журнал аудита |

## Быстрый старт

На хосте, который будет сканировать сеть, от root:

```sh
curl -fsSL https://raw.githubusercontent.com/FlexEbat/Netscribe/main/scripts/get.sh -o get.sh
sudo sh get.sh
```

Мастер установки проверяет хост, предлагает сети для сканирования, пишет конфиг, запускает
сервис и создаёт первого администратора. Каждое изменение спрашивает подтверждение, а `q`
выходит на любом вопросе. Когда мастер закончит, откройте `http://127.0.0.1:8080` и войдите.
Дальше команда `netscribe` без аргументов открывает [консоль](#команда-netscribe).

## Команда `netscribe`

В терминале `sudo netscribe` открывает меню, которое охватывает всю программу:

| Пункт | Что делает |
| --- | --- |
| Watch | Живой обзор сервиса, панели и хоста, с событиями с момента запуска |
| Check | Все проверки `netscribe doctor` с исправлением к каждой находке |
| Scan | Скан сетей из конфига, с Nmap или сетей, которые вы назовёте |
| Devices | Устройства, найденные к этому моменту |
| Export | Документация в Markdown, HTML, PDF или Draw.io |
| Settings | Каждая настройка конфига, хосты SSH, возврат к прежнему конфигу, ваш редактор |
| Accounts | Список, добавление, смена пароля, отключение |
| Service | Статус, запуск, остановка, перезапуск, перечитать конфиг, автозапуск, журнал |
| Setup | Мастер установки ещё раз: пропускает сделанное и чинит несделанное |
| Commands | Все команды для скриптов и cron |

Два правила действуют в каждом меню и на каждом вопросе:

- **Выход есть всегда.** `b` возвращает из любого подменю, где есть пункт Back, а `q`
  (или `quit`, `exit`, Ctrl-D) выходит из программы на любом вопросе.
- **Без «да» ничего не меняется.** Любое действие, которое меняет систему, конфиг, учётку
  или сервис, сначала спрашивает и называет, что сделает. Ответ «нет» ничего не меняет.

Всё, что делает консоль, есть и командой, поэтому работает в скриптах:

| Команда | Назначение |
| --- | --- |
| `netscribe serve` | Запустить веб-панель |
| `netscribe scan [--nmap] [CIDR...]` | Просканировать сети из конфига или указанные CIDR |
| `netscribe devices` | Вывести найденные устройства |
| `netscribe export --format md\|html\|pdf\|drawio --out FILE` | Записать документацию |
| `netscribe user add\|list\|disable\|passwd NAME` | Управлять учётками |
| `netscribe setup` | Мастер установки; с `--yes`, `--admin`, `--listen` и другими флагами ничего не спрашивает |
| `netscribe config [show\|get KEY\|set KEY VALUE\|edit]` | Читать и менять конфиг с проверкой перед сохранением |
| `netscribe watch [--once]` | Живой обзор; `--once` печатает одну выборку и выходит с кодом 1, если сервис не работает |
| `netscribe doctor` | Проверить установку и сказать, что исправить; при ошибке выходит с кодом 1 |
| `netscribe version` | Вывести версию сборки |

Команды, которые читают конфиг, принимают `--config FILE`.

### Мастер установки

`get.sh` ставит команду `netscribe` и запускает `netscribe setup`. Без опций это диалог в
терминале. С опциями он работает без вопросов, например:

```sh
printf '%s\n' "$ADMIN_PASSWORD" | sudo sh get.sh --yes --admin alice --password-stdin --targets 192.168.1.0/24
```

`sudo netscribe setup --dry-run` печатает, что сделал бы мастер, и ничего не меняет.
`sudo netscribe doctor` проверяет установку позже.

### Скрипт install.sh

Классический скрипт ставит бинарник релиза, пользователя сервиса, конфиг в `/etc/netscribe`
и, при systemd, юнит. Конфиг и учётку вы делаете сами:

```sh
curl -fsSL https://raw.githubusercontent.com/FlexEbat/Netscribe/main/scripts/install.sh -o install.sh
sudo sh install.sh
```

### Бинарник

Скачайте архив для своей платформы со [страницы релизов](https://github.com/FlexEbat/Netscribe/releases),
распакуйте и запустите панель:

```sh
tar -xzf netscribe_*_linux_amd64.tar.gz
cp netscribe.example.yaml netscribe.yaml && chmod 600 netscribe.yaml
# укажите scan.targets в netscribe.yaml, затем:
./netscribe serve
```

### Docker

Compose-файл собирает образ из чистого клона и запускает сервис в сети хоста, потому что
ARP и сканирование портов должны достать до вашей локальной сети:

```sh
docker compose -f deploy/compose.yaml up --build -d
curl http://127.0.0.1:8080/healthz
```

Сервис слушает `127.0.0.1:8080` хоста. Если порт занят другой программой, сервер
предупредит и в терминале спросит другой; `--auto-port` берёт следующий свободный порт, а
`--listen ADDRESS` задаёт свой, см. [Решение проблем](docs/troubleshooting.ru.md#порт-уже-занят).
Все остальные маршруты отвечают `503`, пока вы не создадите первого пользователя.

Контейнер работает от пользователя `65532` без capabilities, с корневой файловой системой
только на чтение и `no-new-privileges`. База лежит в томе `data`. Compose-файл монтирует
`netscribe.example.yaml` только на чтение, чтобы первый запуск обошёлся без правок. Свой
конфиг подключается через `NETSCRIBE_CONFIG`:

```sh
cp netscribe.example.yaml netscribe.yaml
chmod 600 netscribe.yaml
sudo chown 65532 netscribe.yaml
NETSCRIBE_CONFIG=../netscribe.yaml docker compose -f deploy/compose.yaml up -d
```

Compose-файл передаёт `--allow-loose-permissions`, потому что пример читается всеми.
Уберите флаг из `command`, когда перейдёте на файл с режимом `0600`. В образе нет Chromium,
поэтому PDF-экспорт внутри него не работает: распечатайте HTML-экспорт в PDF из браузера.

### Из исходников

Нужны Go 1.26 и Node 22: выполните `make build`. На хосте, где нет ни того, ни другого,
`sh scripts/install-build-deps.sh` ставит их вместе с `git` и `make`.

## Первый пользователь

Учётки по умолчанию в панели нет. Мастер установки создаёт первого администратора. При
другом способе установки создайте его командой `user`:

```sh
./netscribe user add alice --role admin
```

В Docker выполните команду внутри контейнера (пока контейнер использует пример конфига,
добавьте `--allow-loose-permissions`):

```sh
docker compose -f deploy/compose.yaml exec netscribe netscribe user add alice --role admin --allow-loose-permissions
```

Пароль не короче 12 символов и не должен быть частым паролем. Роли:

| Роль | Может |
| --- | --- |
| `viewer` | Читать топологию |
| `operator` | Читать, запускать сканы, править устройства и связи |
| `admin` | Всё, включая учётки, токены и журнал аудита |

## Конфигурация

В `netscribe.example.yaml` перечислены все ключи с значениями по умолчанию и комментариями.
Ключи меняют через `sudo netscribe config` (меню), `sudo netscribe config set KEY VALUE` или
правкой файла. Ключи, которые задают в первую очередь:

| Ключ | Значение |
| --- | --- |
| `listen` | Адрес панели. По умолчанию `127.0.0.1:8080` |
| `database` | Путь к файлу SQLite |
| `scan.targets` | CIDR для сканирования, например `192.168.1.0/24` |
| `scan.interval` | Интервал между сканами по расписанию. `0` выключает расписание, минимум `1m` |
| `snmp.communities` | Сообщества SNMP v2c для перебора. Берите сообщество только для чтения |
| `ssh.hosts` | Хосты для чтения по SSH, у каждого пользователь и файл ключа |
| `docker.enabled` | Читать контейнеры из сокета Docker |
| `discovery.httpHeaders` | Один `HEAD /` на открытые веб-порты (80, 443, 8080), заголовок `Server` сохраняется |
| `discovery.mdns` | Один запрос mDNS в каждом локальном сегменте |
| `discovery.ssdp` | Один `M-SEARCH` SSDP в каждом локальном сегменте |
| `discovery.nmap` | Спросить установленный Nmap об устройствах, которые ничем другим не определились. По умолчанию выключено |
| `discovery.nmapScope` | `untyped` (по умолчанию) или `all`: все устройства с открытым портом |
| `discovery.nmapPath` | Абсолютный путь к `nmap`. Пусто: искать в `PATH` |

**Перезагрузка.** Сервер перечитывает файл при изменении и по `SIGHUP`. Новые значения
`scan`, `snmp`, `ssh`, `docker`, `history` и `export` применяются без перезапуска, а идущий
скан доживает с настройками, с которыми начал. Изменение `listen`, `database`, `auth`, `tls`,
`audit`, `discovery`, `trustedProxies` или `allowPublicTargets` требует перезапуска, и журнал
об этом сообщает. Файл, не прошедший проверку, оставляет в работе прежний конфиг, а
администраторы видят ошибку в панели. `netscribe config` говорит, какой из случаев у вашей правки.

## Определение устройств через Nmap

Netscribe определяет тип устройства по SNMP, LLDP, HTTP, mDNS, SSDP и открытым портам.
Устройство, которое ничем из этого не определилось, остаётся `unknown`. Если установлен
[Nmap](https://nmap.org), Netscribe может спросить его только об этих устройствах. Nmap
угадывает ОС и тип устройства по тому, как отвечает стек TCP/IP, а догадка с точностью не
ниже 85 процентов превращается в вид устройства правилами `nmap` из `classify_rules.csv`.

По умолчанию выключено, потому что это шумно: для каждого такого устройства Nmap
сканирует 100 самых частых TCP-портов и отправляет пробы определения ОС. Используйте только
в сетях, которыми вы владеете.

- **Один скан, командная строка:** `netscribe scan --nmap`.
- **Один скан, панель:** отметьте «Identify unknown devices with Nmap» рядом с «Run scan».
- **Каждый скан,** включая плановые: `discovery.nmap: true` или включите в `netscribe config`
  (мастер установки тоже предлагает поставить Nmap).

Определение ОС требует raw-сокетов. Под systemd мастер выдаёт их сервису в drop-файле, и это
не расширяет доступ остальным пользователям. Для бинарника, который вы запускаете сами,
выдайте права самому `nmap` (тогда любой локальный пользователь сможет запускать им raw-сканы,
так что решите, согласны ли вы):

```sh
sudo setcap cap_net_raw,cap_net_admin,cap_net_bind_service+eip "$(command -v nmap)"
```

Без них Nmap завершается с ошибкой, Netscribe один раз пишет причину в журнал, пропускает
этап и заканчивает скан.

Nmap запускается только для устройств хотя бы с одним открытым TCP-портом. Чтобы спросить об
одном устройстве, откройте его в топологии и нажмите «Identify with Nmap»: это работает для
любого устройства, заполняет строку системы и задаёт вид, только пока вид `unknown` и не
задан вручную. Догадка показывается как «System (Nmap)». Устройство, у которого семейство ОС
по Nmap Windows, macOS, Android или Apple iOS, становится `host`; Cisco IOS отличается по
производителю и никогда не становится `host`; Linux-хост для Nmap `general purpose`, поэтому
его вид остаётся прежним. Изменение, которое внёс Nmap, видно на странице Changes как
`Nmap: <устройство> changed: ...` и записано в последний завершённый скан.

**Docker.** В образе по умолчанию Nmap нет. Возьмите вариант с Nmap и его compose-файл:

```sh
docker compose -f deploy/compose.nmap.yaml up --build -d
```

Он возвращает контейнеру `NET_RAW`, `NET_ADMIN` и `NET_BIND_SERVICE` и не ставит
`no-new-privileges`, потому что при этой опции ядро игнорирует файловые capabilities.
Пользователь всё равно не root, а корневая файловая система остаётся только на чтение.

## Экспорт

```sh
netscribe export --format md --out network.md
netscribe export --format html --out network.html
netscribe export --format drawio --out network.drawio
netscribe export --format pdf --out network.pdf   # нужен Chromium или Chrome
```

Панель и консоль предлагают те же форматы. Для PDF ищутся `chromium` и `google-chrome` в
`PATH`; другую программу задаёт `export.chromePath`. В Docker запишите файл в том и
скопируйте наружу:

```sh
docker compose -f deploy/compose.yaml exec netscribe netscribe export --format md --out /data/network.md --allow-loose-permissions
docker compose -f deploy/compose.yaml cp netscribe:/data/network.md .
```

## TLS и обратный прокси

Панель отдаёт обычный HTTP, пока не заданы `tls.certFile` и `tls.keyFile`. Вне интерфейса
loopback используйте один из вариантов:

- Задайте `tls.certFile` и `tls.keyFile` и оставьте в `listen` нужный адрес.
- Поставьте перед панелью обратный прокси, который завершает TLS, оставьте `listen` на
  `127.0.0.1` и перечислите прокси в `trustedProxies`, чтобы Netscribe доверял его
  заголовкам `X-Forwarded-*`.

Мастер установки спрашивает, какой вариант нужен, когда вы выбираете адрес вне loopback.

## Безопасность

Netscribe хранит карту вашей сети: относитесь к его базе и конфигу как к чувствительным данным.

- **Файл конфига.** В нём сообщества SNMP и пути к ключам. Сервис не запускается, если файл
  читается другими пользователями, пока вы не передадите `--allow-loose-permissions`.
  Строки сообществ вводятся без эха и никогда не печатаются.
- **HTTP, mDNS и SSDP.** Каждый источник включается отдельно в разделе `discovery`; выключенный
  источник не отправляет ни одного пакета. HTTP-этап отправляет `HEAD /` без учётных данных,
  читает не больше 8 КиБ заголовков за 2 секунды, никогда не читает тело и не идёт по
  редиректам. mDNS и SSDP отправляют по одному пакету с каждого локального интерфейса и не
  выходят из его сегмента. Всё, что возвращают эти источники, считается недоверенным: оно
  обрезается, очищается от управляющих символов и показывается как простой текст.
- **SNMP v2c** передаёт сообщество открытым текстом. Берите сообщество только для чтения и
  ограничьте его списком доступа на устройстве.
- **Цели скана** ограничены диапазонами RFC 1918, шире /16 нельзя. `allowPublicTargets` снимает
  ограничение; включайте его только для сетей, которыми вы владеете.
- **SSH.** Ключи хостов проверяются строго: хост, которого нет в `ssh.knownHosts`, или хост с
  изменившимся ключом пропускается. Берите учётку, которая может только читать: скан запускает
  `hostname`, `uname -sr`, `ip -o addr` и `ss -H -tln`, и ничего больше.
- **Сокет Docker.** Netscribe отправляет только запросы `GET`, но монтирование только на чтение
  не делает API Docker доступным только на чтение: другой процесс, который достаёт до сокета,
  может запускать контейнеры от root. Если данные контейнеров не нужны, поставьте
  `docker.enabled: false`. Чтобы сохранить данные и сузить доступ, поставьте перед демоном
  фильтрующий прокси, который пропускает только `containers`, `networks` и `events`, и
  направьте `docker.socket` на его unix-сокет ([docker-socket-proxy](https://github.com/Tecnativa/docker-socket-proxy)
  слушает TCP и требует моста в unix-сокет).
- **Сообщения об ошибках безопасности.** Отправляйте так, как описано в [SECURITY.md](SECURITY.md).

```sh
make gate    # линтер, проверка типов и тесты: те же проверки, что в CI
```

Чтобы проверить скан на известных хостах, поднимите лабораторию и запустите lab-тест:

```sh
docker compose -f deploy/compose.lab.yaml up --build -d
go test -tags lab ./cmd/netscribe -run Lab
```
