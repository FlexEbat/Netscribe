# AGENTS.md

Instructions for coding agents and for people who work with them. Read [tech.md](tech.md)
first: it is the source of truth for names, contracts and security parameters, and this
file only summarizes how to work with it.

## Project

Netscribe scans a local network and documents it. One static Go binary serves an embedded
React panel and keeps its data in one SQLite file. The stack is Go (chi, `modernc.org/sqlite`,
goose, sqlc, gosnmp, `x/crypto/ssh`) on the backend and React, TypeScript and Vite on the
frontend. Linux is the only platform.

## Commands

```sh
make gate    # lint, typecheck and tests: the checks CI runs on a pull request
make fmt     # gofmt and prettier
make test    # go test -race ./..., vitest
make gen     # sqlc generate, after any change to internal/store/queries
make audit   # govulncheck and npm audit, needs the network
make build   # frontend, then one binary
make dev     # backend with reload and the Vite dev server
```

`make gate` red means the work is not done. Run it before you push. Tests that need the
lab (`deploy/compose.lab.yaml`) carry the build tag `lab` and stay out of the gate.

A machine without the toolchain can install Go and Node.js with
`sh scripts/install-build-deps.sh`.

## Layout and import rules

- `cmd/netscribe` holds the commands `serve`, `scan`, `devices`, `export`, `user`, `setup`,
  `doctor`, `console`, `watch` and `config`.
- `internal/collector` does not import `store`. A collector returns a `Result`, and
  `scanner` stores it through `Repo.ApplyResult`.
- `internal/render` imports neither `collector` nor `api`.
- `internal/api` holds no SQL and calls no collector directly.
- `internal/setup` imports only `config` and `update`. It reaches the machine through `setup.Env`, and a
  test never touches `/etc`.
- `internal/auth` imports neither `api` nor `store`. It reaches the data through `AuthRepo`.
- `internal/notify` imports only `config` and `model`. `cmd/netscribe` hands it every finished scan from the events hub.
- SQL lives only in `internal/store/migrations` and `internal/store/queries`.
  `internal/store/db` is generated by sqlc: change the query and run `make gen`, never edit
  the generated file by hand.
- Routes are registered only through the route table in `internal/api/router.go`, each with
  a permission. Handlers never compare roles.
- The frontend talks to the server only through `web/src/api/`. Components do not call
  `fetch`.
- A value of type `config.Secret` is never logged, serialized or exported.

## Rules

1. **Contracts.** Table, field, type, route and config names come from tech.md. When a
   contract is missing, stop and write a `CONTRACT GAP` block (tech.md section 14) instead of
   inventing one. The project owner changes tech.md.
2. **Security parameters** of tech.md section 9 are never weakened for convenience. That
   covers cookies, headers, limits, timeouts, session lifetimes, the private-range limit of
   scan targets and the fixed read-only SSH commands.
3. **Network code** runs only against the lab, fixtures or networks the project owner owns.
4. **Tests come from acceptance criteria**, not from the implementation. A test that writes
   a value and reads the same value back proves nothing. Every refusal path has a test of
   the refusal.
5. **No timing guesses in tests.** Do not wait with a fixed `time.Sleep` for something to
   start or finish: wait on a channel, a hook or a poll with a deadline, and do not pace
   events with sleeps shorter than the delays under test. Write files atomically
   (temporary file, then rename) when a watcher reads them.
6. **Surgical changes.** Do not refactor working code next to the change. Every changed line
   follows from the task. No dead code, no commented-out code, no new files or abstractions
   beyond tech.md section 3 without a reason in the pull request.
7. **One change at a time**, and review in a second pass: after the code works and the gate
   is green, go through the checklist of tech.md section 17 and look for problems.
8. **Errors** are returned or logged. `_ =` needs a comment that says why the error does
   not matter.
9. **Data from the network** (host names, `sysDescr`, container names) is normalized when it
   is stored and escaped when it is shown. `dangerouslySetInnerHTML` is not used.

## Writing

Code, comments, commits, logs, interface text and documentation are in English. Use the
active voice, name the concrete thing, skip introductory phrases, the long dash and
intensifying adverbs. A comment explains why, not what the next line does.

Commits follow `type(scope): summary`:

- `type`: `feat`, `fix`, `test`, `refactor`, `chore`, `docs`
- `scope`: `config`, `store`, `collector`, `render`, `api`, `web`, `deploy`
- the summary is imperative, lower case, without a period, up to 50 characters
- the body explains why, not what

Commit in small steps. Each commit should pass `make check`.

## Definition of done

The acceptance criteria hold and were checked by hand (browser for the interface, terminal
for the CLI). Tests exist and `make gate` is green. `sqlc diff` is empty. Every new route is
in the route table with a permission and has tests for 401 and 403. Commits follow the
convention.
