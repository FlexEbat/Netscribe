# Установка

[English](installation.md) · **Русский**

Netscribe работает на любом дистрибутиве Linux, amd64 или arm64. Бинарник релиза статический:
ему не нужны ни библиотеки, ни Go, ни Node.js на хосте, и для запуска ничего устанавливать не
надо. Nmap, Chromium и Docker необязательны, и каждый включает одну возможность.

| Способ | Когда использовать |
| --- | --- |
| [Мастер установки](#мастер-установки) | Нужны проверки, рекомендации и первая учётка за один запуск (рекомендуется) |
| [Скрипт install.sh](#скрипт-installsh) | Нужны пользователь сервиса, конфиг и юнит systemd за один шаг, а конфиг вы правите сами |
| [Бинарник релиза вручную](#бинарник-релиза-вручную) | Пользователей, пути и систему инициализации вы ведёте сами |
| [Docker](#docker) | На хосте уже работают контейнеры |
| [Сборка из исходников](#сборка-из-исходников) | Вы разрабатываете Netscribe или вам нужен невыпущенный коммит |

## Мастер установки

`get.sh` ставит команду `netscribe` и запускает `netscribe setup`, который делает остальное и
объясняет каждый шаг. Есть два режима:

- **Без опций** это диалог в терминале. Он задаёт несколько важных вопросов, отмечает
  проблемы и говорит, как их исправить. Когда он заканчивает, `netscribe` становится
  самостоятельной командой: набранная без аргументов в терминале, она открывает
  [консоль](#консоль).
- **С опциями** (`--yes`, `--admin`, `--listen` и другие ниже) он ничего не спрашивает и
  может работать из скрипта развёртывания.

В диалоге каждое изменение сначала спрашивает: создание учётки, каталогов, конфига, каждого
файла юнита. Enter берёт ответ в скобках, `n` пропускает изменение и останавливает установку
до него, а `q` (или `quit`, `exit`, Ctrl-D) выходит на любом вопросе. Мастер говорит, на каком
шаге остановился. Сделанное остаётся сделанным, и повторный запуск продолжает с этого места.
Пароль первого администратора вводится в самой команде `netscribe user add`, которая читает
его без эха; из этого запроса выходят по Ctrl-C.

Запускайте на хосте, который будет сканировать сеть, от root:

```sh
curl -fsSL https://raw.githubusercontent.com/FlexEbat/Netscribe/main/scripts/get.sh -o get.sh
sudo sh get.sh
```

`--version`, `--prefix` и `--base-url` уходят в `install.sh`, который `get.sh` использует,
чтобы скачать релиз и проверить его контрольную сумму. Все остальные опции уходят в
`netscribe setup`. Если запускать через `curl`, вопросы читаются с терминала.

Мастер проходит девять шагов. Каждый печатает найденное, отмечает проблему знаком `!` или `✗`
и говорит, как её исправить:

| Шаг | Что проверяет и делает |
| --- | --- |
| System | Linux и архитектура, root, systemd, свободное место для данных |
| The netscribe command | Копирует бинарник в `/usr/local/bin/netscribe`, если он запущен из другого места |
| Service account | Создаёт учётку `netscribe` и каталоги `/etc/netscribe` и `/var/lib/netscribe` с режимом 0750 |
| Features | Предлагает поставить Nmap и Chromium пакетным менеджером и ищет сокет Docker |
| Configuration | Предлагает частные сети хоста как цели скана, спрашивает, [где слушает панель](#где-слушает-панель), и интервал скана, и пишет `netscribe.yaml` с режимом 0600. Существующий конфиг не перезаписывается |
| ICMP probes | Читает `net.ipv4.ping_group_range`. Если ICMP echo выключен для всех групп, пишет `/etc/sysctl.d/99-netscribe.conf` для группы сервиса |
| First administrator | Запускает `netscribe user add` от учётки сервиса, если учёток нет, чтобы база принадлежала сервису |
| Service | Ставит юнит, добавляет drop-in для группы Docker и для Nmap, запускает сервис и ждёт ответа панели |
| Result | Выполняет все проверки заново, перечисляет оставшееся с исправлением к каждому пункту и предлагает открыть консоль |

Мастер предлагает сети, найденные на интерфейсах. Сеть шире /24 сужается до /24 адреса, а
интерфейсы контейнеров и виртуальных машин пропускаются. Он пишет только те ключи, о которых
спросил. Остальные ключи остаются по умолчанию, а `netscribe.example.yaml` перечисляет их все.

Опции `netscribe setup`:

| Опция | Значение |
| --- | --- |
| `--dry-run` | Напечатать план и конфиг, который был бы записан. Ничего не менять |
| `--yes` | Взять рекомендуемый ответ на каждый вопрос. Нужно, когда терминала нет |
| `--admin NAME` | Создать первого администратора с этим именем. Добавьте `--password-stdin`, чтобы читать пароль со стандартного ввода |
| `--targets LIST` | Цели скана нового конфига, CIDR через запятую |
| `--listen ADDR` | Адрес прослушивания нового конфига, по умолчанию `127.0.0.1:8080` |
| `--tls-cert FILE`, `--tls-key FILE` | Панель отдаёт TLS с этими сертификатом и ключом. Нужны при адресе вне loopback, если не указан прокси или `--plain-http` |
| `--trusted-proxy LIST` | Адрес или сеть обратного прокси перед панелью, через запятую |
| `--plain-http` | Принять адрес вне loopback без TLS и без прокси |
| `--no-service` | Не ставить юнит и ничего не запускать |
| `--config PATH` | Файл конфига, который записать или сохранить, по умолчанию `/etc/netscribe/netscribe.yaml` |

Установка без вопросов:

```sh
printf '%s\n' "$ADMIN_PASSWORD" | sudo sh get.sh --yes --admin alice --password-stdin --targets 192.168.1.0/24
```

### Где слушает панель

Мастер предлагает четыре места, и тот же список есть в `netscribe config`:

| Выбор | Значение |
| --- | --- |
| `127.0.0.1:8080` | Только этот хост. Рекомендуемое значение по умолчанию: к панели подключаются через `ssh -L 8080:127.0.0.1:8080 user@host` или ставят перед ней обратный прокси с TLS на том же хосте |
| Адрес интерфейса, например `192.168.1.20:8080` | Открыто только в эту сеть. Одна запись на каждый найденный интерфейс, мосты контейнеров не показываются |
| `0.0.0.0:8080` | Открыто во все сети хоста |
| Другой адрес | Любой `host:port`, который хост может занять |

Адрес вне loopback передаёт пароли и cookie сессий по сети, поэтому мастер тогда спрашивает,
чем защищён трафик: обратный прокси с TLS на другом хосте (его адрес идёт в
`trustedProxies`), сертификат и ключ для самой панели (проверяется, что они парные, пишутся в
`tls`) или обычный HTTP после явного «да». В скрипте те же ответы дают опции `--tls-cert` и
`--tls-key`, `--trusted-proxy` и `--plain-http`.

### Консоль

Когда установка закончена, `netscribe` без аргументов в терминале открывает меню, которое
охватывает всю программу. Запускайте с `sudo`: конфиг и база принадлежат учётке сервиса.

| Пункт | Что делает |
| --- | --- |
| Watch | Живой обзор ниже |
| Check | Проверки `netscribe doctor` |
| Scan | Скан сетей из конфига, то же с Nmap или сетей, которые вы назовёте. Скан идёт от учётки сервиса и показывает ход; Ctrl-C прерывает скан, а не консоль |
| Devices | Устройства, найденные к этому моменту |
| Export | Markdown, HTML, PDF или Draw.io в файл, который вы назовёте. Файл принадлежит вам, а не root. Существующий файл заменяется только после вашего «да» |
| Settings | Каждая настройка конфига со значением и советом, хосты SSH, файл в вашем редакторе и возврат к прежнему конфигу |
| Accounts | Список, добавление, смена пароля и отключение, от учётки сервиса |
| Service | Статус, запуск, остановка, перезапуск, перечитать конфиг, автозапуск, журнал |
| Setup | Мастер установки ещё раз. Пропускает сделанное и чинит несделанное |
| Commands | Все команды с аргументами для скриптов и cron |

В каждом меню и на каждом вопросе есть выход, и без «да» ничего не меняется:

- `b` возвращает из любого подменю, где есть пункт Back. `q`, `quit`, `exit` или Ctrl-D
  выходят из всей консоли на любом вопросе, как бы глубоко вы ни зашли.
- Запуск скана, запись экспорта, запуск, остановка и перезапуск сервиса, добавление, сброс
  пароля и отключение учётки, сохранение настройки, правка хостов SSH, возврат конфига и
  повторный запуск мастера сначала спрашивают и говорят, что сделают. Ответ «нет» ничего не
  меняет. Чтение (статус, журнал, список, устройства, проверка, наблюдатель) ничего не спрашивает.

### Наблюдатель

`netscribe watch` обновляет экран каждые две секунды (`--interval`) до Ctrl-C:

- сервис: состояние, с какого времени, перезапуски, стартует ли при загрузке;
- панель: отвечает ли, как быстро, и последние 28 ответов графиком;
- процесс: CPU, память, потоки и открытые файлы;
- данные: размер базы и её журнала, свободное место на диске;
- хост: нагрузка и свободная память;
- конфиг: корректен ли и когда менялся;
- события: что изменилось с запуска наблюдателя, например сервис остановился, панель
  перестала отвечать, перезапуск, конфиг перестал загружаться, осталось меньше 256 МиБ на
  диске, скачок памяти. Плохое событие звонит в терминал;
- последние строки журнала сервиса.

`netscribe watch --once` печатает одну выборку и выходит с кодом 1, если сервис не работает или
панель не отвечает, поэтому его можно вызывать из мониторинга или cron.

### Настройки

`netscribe config` открывает редактор: доступ к панели, сканирование, обнаружение, Docker,
SNMP, история, политика входа, экспорт, SSH и список хостов SSH, у каждой настройки значение,
пояснение и рекомендуемое значение. Каждое изменение показывает старое и новое значение и
спрашивает перед сохранением. Изменение проверяется вместе со всем конфигом до сохранения,
старый файл остаётся как `netscribe.yaml.bak`, а комментарии вашего файла сохраняются.
«Restore the previous config» меняет файл местами с этим `.bak`, поэтому обмен можно отменить.
Редактор говорит, применит ли работающий сервис изменение сам (ключи `scan`, `snmp`, `ssh`,
`docker`, `history` и `export`) или нужен перезапуск, и предлагает перезапустить. Строки
сообществ вводятся без эха и больше не показываются.

Для скриптов:

```sh
sudo netscribe config show                        # файл, секреты скрыты
sudo netscribe config get scan.interval
sudo netscribe config set scan.interval 30m
sudo netscribe config set scan.targets 10.0.0.0/24 10.0.1.0/24
sudo netscribe config edit                        # ваш редактор, проверка перед сохранением
```

### Проверка установки

`netscribe doctor` выполняет те же проверки, ничего не меняя, печатает их по областям и
выходит с кодом 1, если проверка не прошла. Запускайте от root: конфиг принадлежит учётке
сервиса и закрыт для остальных.

```sh
sudo netscribe doctor
```

Он сообщает о конфиге, который не загружается, о конфиге, который учётка сервиса не может
прочитать, о порте, занятом другой программой, о панели, слушающей сеть без TLS, о целях
скана, которые не совпадают ни с одной сетью хоста, об ICMP, который группа сервиса не может
отправлять, о Nmap без прав на raw-сокеты, о сокете Docker, который сервис не может
использовать, об остановленном сервисе, о панели, которая не отвечает, и о базе без учёток.

## Скрипт install.sh

```sh
curl -fsSL https://raw.githubusercontent.com/FlexEbat/Netscribe/main/scripts/install.sh -o install.sh
sudo sh install.sh
```

Прочитайте скрипт перед запуском. Он делает следующее:

1. Определяет архитектуру и последний релиз (`--version v1.2.0` выбирает другой).
2. Ставит `tar`, `sha256sum` и `curl` пакетным менеджером, если их нет.
3. Скачивает архив и `checksums.txt` и останавливается, если сумма не совпала.
4. Копирует бинарник в `/usr/local/bin` (`--prefix DIR` меняет каталог).
5. Создаёт системного пользователя `netscribe`, каталог `/var/lib/netscribe` для базы и
   `/etc/netscribe/netscribe.yaml` с режимом `0600`. Существующий конфиг остаётся как есть.
6. На хосте с systemd ставит `netscribe.service`. Работающий сервис при обновлении
   перезапускается, остановленный остаётся остановленным.

Опции:

| Опция | Действие |
| --- | --- |
| `--with-nmap` | Поставить Nmap пакетным менеджером для [определения устройств](../README.ru.md#определение-устройств-через-nmap) |
| `--with-chromium` | Поставить Chromium для PDF-экспорта |
| `--no-service` | Поставить только бинарник |
| `--base-url URL` | Скачивать с `URL/TAG/`, а не с GitHub, для зеркала |
| `--uninstall` | Удалить бинарник и юнит, оставить конфиг и данные |

Скрипт знает apt, dnf, yum, zypper, pacman, apk и xbps. В другой системе он всё равно ставит
релиз, если `tar`, `sha256sum` и `curl` или `wget` уже есть.

Когда скрипт закончил:

```sh
sudo -u netscribe ${EDITOR:-vi} /etc/netscribe/netscribe.yaml      # задайте scan.targets
sudo -u netscribe /usr/local/bin/netscribe user add alice --role admin --config /etc/netscribe/netscribe.yaml
sudo systemctl enable --now netscribe
```

Правьте конфиг от пользователя `netscribe`: сервер отказывается от конфига, который читают
другие пользователи, а файл, сохранённый от root с другим владельцем, становится нечитаемым
для сервиса. Сервер перечитывает файл при изменении, а `sudo systemctl reload netscribe`
делает это принудительно.

Юнит запускает сервис с `NoNewPrivileges`, файловой системой только на чтение вне
`/var/lib/netscribe` и ограниченным набором семейств адресов. Чтобы читать данные Docker,
укажите группу, владеющую сокетом, в `SupplementaryGroups=` юнита.

## Проверка загрузки

`checksums.txt` показывает, что загрузка полная. Каждый релиз также несёт подписанное
свидетельство о том, где собраны его архивы: репозиторий, коммит и workflow. Проверьте архив
по нему с помощью GitHub CLI:

```sh
gh attestation verify netscribe_0.1.2_linux_amd64.tar.gz --repo FlexEbat/Netscribe
```

У релиза, выпущенного до появления этого свидетельства, его нет, и команда об этом скажет.

## Бинарник релиза вручную

```sh
tar -xzf netscribe_*_linux_amd64.tar.gz
cp netscribe.example.yaml netscribe.yaml && chmod 600 netscribe.yaml
./netscribe user add alice --role admin
./netscribe serve
```

Сверьте архив с `checksums.txt` релиза командой `sha256sum -c`. На хосте без systemd
запускайте `netscribe serve --config PATH` из вашей системы инициализации от непривилегированного
пользователя и посылайте `SIGHUP`, чтобы перечитать конфиг.

## Сборка из исходников

Нужны Go (версия из `go.mod`), Node.js 22, `git` и `make`. Хост без них:

```sh
sh scripts/install-build-deps.sh
```

Скрипт ставит `git` и `make` пакетным менеджером, а Go и Node.js берёт из их официальных
архивов после проверки контрольных сумм: в `/usr/local` от root или в `~/.local` от обычного
пользователя (`--prefix DIR` выбирает другое место, `--dry-run` печатает план). На Alpine и
других системах с musl официальная сборка Node.js не запускается, поэтому там скрипт ставит
Node.js пакетным менеджером.

```sh
make build
./netscribe serve
```

## Необязательные пакеты

| Возможность | Пакет | Debian, Ubuntu | Fedora, RHEL | openSUSE | Arch | Alpine | Void |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Определение через Nmap | nmap | `nmap` | `nmap` | `nmap` | `nmap` | `nmap` | `nmap` |
| PDF-экспорт | Chromium | `chromium` (Ubuntu: `chromium-browser`) | `chromium` | `chromium` | `chromium` | `chromium` | `chromium` |

На RHEL и его клонах включите EPEL перед установкой Chromium. Для PDF-экспорта ищутся
`chromium` и `google-chrome` в `PATH`. Другую программу задаёт `export.chromePath`.

Nmap для определения ОС нужны raw-сокеты. Выдайте сервису права в drop-файле: он не расширяет
доступ остальным пользователям так, как `setcap` на бинарнике:

```ini
# /etc/systemd/system/netscribe.service.d/nmap.conf
[Service]
AmbientCapabilities=CAP_NET_RAW CAP_NET_ADMIN
CapabilityBoundingSet=CAP_NET_RAW CAP_NET_ADMIN
```

Затем выполните `sudo systemctl daemon-reload && sudo systemctl restart netscribe`.

## Сеть и межсетевой экран

По умолчанию панель слушает `127.0.0.1:8080`. Чтобы открыть её с другой машины, поставьте
перед ней обратный прокси с TLS или задайте `tls.certFile` и `tls.keyFile`, см.
[TLS и обратный прокси](../README.ru.md#tls-и-обратный-прокси). Netscribe отправляет пакеты
только на цели, которые вы настроили.

ICMP-пробам нужна группа сервиса в `net.ipv4.ping_group_range`. Без неё Netscribe пишет в
журнал, что ICMP выключен, и проверяет только по TCP. Обнаружение по ARP читает
`/proc/net/arp` и raw-сокета не требует.

Когда порт занят, сервер предупреждает и в терминале спрашивает другой. См.
[Решение проблем](troubleshooting.ru.md#порт-уже-занят).

## Резервное копирование

Всё, что хранит Netscribe, лежит в файле SQLite из ключа `database` (устройства, связи,
учётки, журнал аудита) рядом с конфигом. SQLite работает в режиме WAL, поэтому копия одного
основного файла может потерять последние записи. Остановите сервис и скопируйте файл вместе
с соседями `-wal` и `-shm` или сделайте согласованную копию при работающем сервисе программой
`sqlite3`:

```sh
sqlite3 /var/lib/netscribe/netscribe.db ".backup /var/backups/netscribe.db"
```

В файле хэши паролей и записи сессий: дайте копии режим `0600`.

## Обновление и удаление

Для обновления запустите скрипт установки или мастер ещё раз. Конфиг и база остаются, а
мастер пропускает каждый уже выполненный шаг. Перед крупным обновлением сделайте копию файла
из `database`. `sudo sh install.sh --uninstall` удаляет бинарник и юнит и оставляет
`/etc/netscribe` и `/var/lib/netscribe` на ваше усмотрение.
