# Решение проблем

[English](troubleshooting.md) · **Русский**

## Порт уже занят

При запуске сервер занимает порт раньше всего остального. Если порт держит другая программа,
сервер пишет в журнал `port is already in use` и делает одно из следующего:

- В терминале он спрашивает: введите другой порт, наберите `auto` для следующего свободного
  порта или нажмите Enter, чтобы выйти.
- С `--auto-port` он без вопросов берёт следующий свободный порт выше занятого и пишет в
  журнал, какой выбрал. Он пробует 100 портов.
- Без терминала (сервис, контейнер) и без `--auto-port` он завершается с ошибкой, в которой
  назван адрес.

Чтобы выбрать порт самому, задайте `listen` в `netscribe.yaml` или передайте
`--listen 127.0.0.1:9090` в `netscribe serve`. Флаг сильнее файла. Узнать, кто держит порт:

```sh
sudo ss -ltnp 'sport = :8080'
```

Порт, выбранный при запуске, в конфиг не записывается. Строка журнала `listening` показывает
используемый адрес. Если есть обратный прокси или правило межсетевого экрана, задайте порт в
`listen`, чтобы он не менялся.

## Сервер не запускается

| Сообщение | Причина и исправление |
| --- | --- |
| `config file permissions 0644 are wider than 0600` | Выполните `chmod 600 netscribe.yaml` или передайте `--allow-loose-permissions`, если файловая система не хранит режим, как у некоторых bind-монтирований. |
| `listen: listen must be host:port with a port from 1 to 65535` | Значению нужны двоеточие и порт, например `127.0.0.1:8080`. |
| `parse config: ... field ... not found` | Ключ написан с ошибкой. Неизвестные ключи это ошибки намеренно. |
| `load tls certificate` | `tls.certFile` и `tls.keyFile` не подходят друг другу или недоступны пользователю сервиса. |
| `no users: run "netscribe user add"` (HTTP 503) | Создайте первого администратора, см. README. |

`sudo netscribe doctor` находит большинство из этого и печатает исправление к каждой находке.

## Скан показывается как идущий после перезапуска

Скан, который сервер не закончил, потому что процесс остановился, в старой версии остаётся
`running`. Текущие версии закрывают такие сканы как неудавшиеся при запуске сервера и пишут в
журнал `closed scans that an earlier run left unfinished`.

## Возможность не показывает данных

| Признак | Исправление |
| --- | --- |
| Нет устройств | Проверьте `scan.targets`. Цели вне частных диапазонов требуют `allowPublicTargets: true`, а цель не может быть шире /16. Сканер читает ARP локального сегмента и проверяет остальные цели по ICMP и TCP. |
| `ICMP probes are off, TCP probes only` | Справочное сообщение. Разрешите группу сервиса в `net.ipv4.ping_group_range`, чтобы получить ICMP. |
| `dnet: Failed to open device` в журнале | У Nmap нет прав на raw-сокеты. См. [Необязательные пакеты](installation.ru.md#необязательные-пакеты). |
| PDF-экспорт не работает | Поставьте Chromium или задайте `export.chromePath`. В образе Docker его нет. |
| Нет контейнеров Docker | Пользователю сервиса нужен доступ к `docker.socket`. Под systemd укажите группу в `SupplementaryGroups=`. |
| Хост по SSH пропускается | Хоста нет в `ssh.knownHosts` или его ключ изменился. Добавьте ключ через `ssh-keyscan`. |
| SNMP ничего не показывает | Проверьте сообщество, список доступа на устройстве и `snmp.timeout`. |

## Конфиг не перечитывается

Причину показывают журнал и панель (администраторам). Файл, не прошедший проверку, оставляет
в работе прежний конфиг. Изменения `listen`, `database`, `auth`, `tls`, `audit`, `discovery`,
`trustedProxies` и `allowPublicTargets` требуют перезапуска, и журнал об этом говорит.

Когда вы правите файл от root, владелец может измениться. Пользователь сервиса должен быть его
владельцем или мочь прочитать его при режиме `0600`.

## Сессии заканчиваются при открытой странице

Панель держит открытым поток событий. Сервер проверяет учётные данные потока каждые 25
секунд: выход, отключённая учётка, смена пароля или отозванный токен завершают его. Поток не
продлевает таймаут простоя сессии.
