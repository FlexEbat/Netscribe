# Архитектура

[English](architecture.md) · **Русский**

Netscribe это один процесс и один бинарник. Он сканирует цели из конфига, сохраняет найденное
в SQLite и отдаёт веб-панель из того же бинарника.

```
            +-----------+     +-----------+     +---------+
 цели    -> | collector | --> |  scanner  | --> |  store  | <-- api <-- панель (React)
            +-----------+     +-----------+     +---------+       \--> render --> md, html, pdf, drawio
```

## Пакеты

| Пакет | Задача |
| --- | --- |
| `cmd/netscribe` | Команды `serve`, `scan`, `devices`, `export`, `user`, `setup`, `console`, `watch`, `config` и `doctor`. Связывает пакеты и отвечает за запуск и остановку. |
| `internal/setup` | Мастер установки, консоль, наблюдатель, редактор настроек и проверки. Импортирует только `config` и `update` и работает с машиной через `setup.Env`, поэтому тесты никогда не трогают `/etc`. Другие команды он запускает от учётки сервиса, сам базу не открывает. |
| `internal/config` | Загружает и проверяет YAML-файл, хранит тип `Secret` и перечитывает файл при изменении или по `SIGHUP`. |
| `internal/collector` | По одному сборщику на источник: ARP, пробы, SNMP, LLDP, таблицы маршрутизаторов, сервисы, HTTP, mDNS, SSDP, SSH, Docker и Nmap. Сборщик возвращает результат и никогда не трогает базу. Их запускает `scanner`, он же ведёт расписание. |
| `internal/store` | Доступ к SQLite: миграции (goose), запросы (sqlc), слияние результата скана с базой и запись ленты изменений. |
| `internal/auth` | Пароли Argon2id, сессии, токены доступа, роли и ограничение попыток входа. |
| `internal/api` | HTTP-маршруты, цепочка middleware (заголовки, лимиты, аутентификация, CSRF, права, аудит) и поток событий. |
| `internal/render` | Раскладка и экспорт в Markdown, HTML, PDF и Draw.io из сохранённой топологии. |
| `internal/events` | Хаб, который доставляет ход скана и изменения топологии в потоки событий. |
| `web` | Панель на React. Сборка встроена в бинарник. |

Правила импорта, которые сохраняют эту форму, описаны в [AGENTS.md](../AGENTS.md).

## Скан

`scanner` допускает один скан одновременно. Скан выполняет этапы по порядку:

1. **Обнаружение.** ARP находит хосты локального сегмента.
2. **Имена.** Системный резолвер называет хосты. Неработающий резолвер стоит одного таймаута
   на весь скан.
3. **Обогащение.** По порядку: пробы маршрутизируемых подсетей, SNMP, LLDP, таблицы
   маршрутизаторов, сканирование портов сервисов, заголовки HTTP, mDNS и SSDP. Ошибка одного
   источника пишется в журнал, и скан продолжается.
4. **Классификация.** Правила из `classify_rules.csv` превращают факты в вид устройства. Nmap
   спрашивается только об устройствах, которые ничем другим не определились, и только если он
   включён.
5. **Сохранение.** `ApplyResult` сливает результат с базой одной транзакцией: устройства
   сопоставляются по MAC-адресу, а каждое отличие от прошлого скана становится записью ленты
   изменений.
6. **Поздние сборщики.** SSH и Docker добавляют то, что прочитали с настроенных вами хостов.

Скан заканчивается как `done` или `failed`. Неудавшийся скан оставляет устройства как были.
Планировщик запускает скан каждые `scan.interval` и пропускает такт, пока идёт скан.

## Запросы

Запрос проходит middleware в фиксированном порядке: заголовки безопасности, лимит тела,
проверка, что пользователь существует, аутентификация (токен Bearer, иначе cookie сессии),
CSRF для изменений через cookie и право маршрута. Маршруты существуют только в таблице
маршрутов `internal/api/router.go`, каждый с правом. Обработчики никогда не сравнивают роли.

Поток событий (`GET /api/events`) держит соединение открытым и отправляет ход скана и
изменения топологии. Каждые 25 секунд он заново проверяет учётные данные, поэтому выход,
отключённая учётка или отозванный токен завершают поток.

## Запуск и остановка

`serve` загружает конфиг, занимает порт, открывает базу, закрывает сканы, которые прошлый
запуск оставил незавершёнными, и только потом запускает рабочие процессы: обслуживание,
наблюдатель Docker, расписание сканов и наблюдатель конфига. Порт идёт первым, поэтому занятый
порт останавливает команду до запуска любого рабочего процесса. По `SIGINT` или `SIGTERM`
сервер перестаёт принимать запросы, ждёт идущие до 10 секунд и отменяет рабочие процессы через
один контекст.

## Данные

Один файл SQLite в режиме WAL с включёнными внешними ключами. Схема лежит в
`internal/store/migrations`. Пароли хранятся как хэши Argon2id. Идентификаторы сессий
хранятся как хэши SHA-256, поэтому копия базы не содержит пригодной cookie.
